# Figma Code Connect: Button and Link experiment

A small React + TypeScript repository for demonstrating how Figma component properties become component usage examples in Dev Mode. It includes real Button and Link components, a local playground, and two Code Connect template files.

Start here, then follow [the Figma construction guide](docs/figma-setup.md). Use [the experiment plan](docs/experiment-plan.md) for your presentation.

## What you are testing

**Question:** Can explicitly mapping a small Figma library to existing code components give developers accurate, reusable component examples?

The experiment isolates the mechanics of Code Connect. Production integration remains a separate assessment: the real component APIs, Figma properties, documentation conventions, and maintenance ownership need to be checked.

The demonstration uses the CLI with `.figma.ts` template files, which is Figma's currently maintained approach. The older framework-specific React parser is no longer maintained. Code Connect UI is an optional separate workflow for code-path mappings and MCP context; UI-created connections alone currently do not show authored snippets in the Inspect panel.

## 1. Check access and tools

- Code Connect requires a **Figma Organization or Enterprise plan**, with a **Dev or Full seat**. Use a Full seat and edit access if you are creating the library yourself in Figma Design.
- Put the demo file in the eligible organization's team/project. An unrelated personal Starter workspace does not acquire your organization's entitlement.
- Use **Node.js 22.12 or newer** for this starter. Node 24 is a suitable choice. This is the starter's requirement; the standalone Code Connect CLI has a lower minimum.
- You need npm, Git, and a GitHub account for the repository demonstration.
- Your Figma account must be able to access the demo file and publish Code Connect mappings.

Check installed tools:

```bash
node --version
npm --version
git --version
```

GitHub hosting makes the experiment easier to share and supplies useful source links. You do not need the Figma GitHub app, Storybook, an npm-published package, a website deployment, or an MCP client for this CLI demonstration.

## 2. Run the supplied code locally

Unzip this starter and open a terminal in `figma-code-connect-demo`:

```bash
cd figma-code-connect-demo
npm ci
npm run dev
```

Open the local URL printed by Vite, usually `http://localhost:5173`.

Check that changing the controls updates the real components. Click the Button and watch the activation count. Enable Disabled and verify that it stops activating. For Link, External adds an arrow and gives the anchor a new-tab target and an accessible announcement.

The playground displays local reference snippets for comparison. Those are generated by the playground; the actual Code Connect integration is demonstrated in Figma after publishing.

The archive includes a lockfile, so `npm ci` installs its pinned dependencies. For later dependency changes use `npm install` and commit the updated lockfile.

## 3. Create the GitHub repository

On GitHub, create an empty repository named `figma-code-connect-demo`. Leave the automatic README, license, and gitignore options unchecked because this starter already contains files. A public repository is convenient for presentation viewers; a private repository also works with appropriate viewer access.

From the extracted starter folder:

```bash
git init -b main
git add .
git commit -m "Add Button and Link Code Connect experiment"
git remote add origin https://github.com/YOUR_USERNAME/figma-code-connect-demo.git
git push -u origin main
```

Replace `YOUR_USERNAME` with your account or organization. Sign in using your usual GitHub credentials if Git prompts. Choose a repository you control for this experiment.

The supplied `.gitignore` excludes dependencies, build output, and local environment files.

## 4. Build the matching Figma library

Create a Figma Design file called `Code Connect Demo Library`. Add two pages:

1. **Components** for the main component sets.
2. **Demo** for a small frame containing Button and Link instances.

Create the following properties with **exactly these names and values**:

| Component | Figma property | Property type | Values | React output |
| --- | --- | --- | --- | --- |
| Button | Variant | Variant | Primary, Secondary | `variant="primary"` or `"secondary"` |
| Button | Size | Variant | Small, Medium | `size="small"` or `"medium"` |
| Button | State | Variant | Default, Disabled | `disabled={false}` or `{true}` |
| Button | Label | Text | Save changes, or any label | `children` text |
| Link | Variant | Variant | Default, Muted | `variant="default"` or `"muted"` |
| Link | Label | Text | Read documentation, or any label | `children` text |
| Link | External | Boolean | false, true | `external={false}` or `{true}` |

Button uses **8 variants**: every combination of Variant × Size × State. Link uses **2 variants**, plus a Boolean property that controls the visibility of a separate arrow layer.

Follow [docs/figma-setup.md](docs/figma-setup.md) for construction, styling, and binding the text and arrow layers. A layer named Label is not automatically a text property: expose the text content as a component property named Label.

Publish Button and Link using Figma's library publishing controls. The CLI mappings are a separate publication from the Figma design library.

For a fuller library demonstration, create a second Figma Design file called `Code Connect Demo Consumer`, enable the published library in Assets, and insert its Button and Link instances. A separate consumer file is optional; you can first test instances on the Demo page in the library file.

## 5. Insert the Figma component URLs

On the Components page, select the **Button component set**, right-click, and choose **Copy link to selection**. Select the whole main component set, so the mapping covers its variants.

Open:

```text
src/components/Button/Button.figma.ts
```

Replace the entire URL after `// url=` on the first line with the copied URL.

Repeat for the **Link component set** in:

```text
src/components/Link/Link.figma.ts
```

Use the URLs of the main components in the library file. Keep the node-id part. Do not use a detached instance, ordinary frame, entire-file URL, or the consumer-file instance URL.

The other metadata comments identify the component source file and its exported name. The templates read properties from the inspected Figma instance and generate a usage example. The `imports` entries are real paths for a consumer file located directly inside `src`, such as `src/ConsumerDemo.tsx`; adjust them if you demonstrate a different application structure.

Button's State variant is mapped to a Boolean in code. That demonstrates that design and code properties can use different names and types.

Link's `href` is deliberately a fixed documentation URL in this template. This experiment does not extract destinations from Figma prototype interactions. Supporting different destinations would require a deliberate destination-property or template convention.

## 6. Generate a Figma access token

In the Figma file browser:

1. Open your account menu and choose Settings.
2. Open Security.
3. Find Personal access tokens and choose Generate new token.
4. Name it `Code Connect demo`, choose an appropriate expiry, and grant:
   - **Code Connect: Write** (`code_connect:write`).
   - **File content: Read** (`file_content:read`).
5. Copy the token when Figma displays it.

Supply it as `FIGMA_ACCESS_TOKEN` in your terminal. The following works in Bash, including when your macOS Terminal normally starts in Zsh. It prompts with hidden input and does not put the token in a source file:

Start Bash first:

```bash
bash
```

Then run this line, paste the token at the prompt, and press Enter:

```bash
read -r -s -p "Paste Figma token: " FIGMA_ACCESS_TOKEN
```

After entering the token, export it:

```bash
export FIGMA_ACCESS_TOKEN
```

Run the following commands in that same shell, from the repository root. Do not add the token to the repository or a presentation screenshot.

## 7. Check and publish

First verify the app and parse the template files locally:

```bash
npm run build
npm run connect:parse
```

`connect:parse` outputs the connection documents and compiles the templates. It does not prove that the Figma nodes exist or that their property definitions are correct.

Preview publication:

```bash
npm run connect:check
```

This invokes `figma connect publish --dry-run`: it lists the mappings and validates them against the Figma API without uploading them. It requires your token and real component URLs. Treat actual publishing and Dev Mode inspection as the end-to-end checks.

Publish the two mappings:

```bash
npm run connect:publish
```

The scripts use the repository's installed `@figma/code-connect` CLI. The equivalent direct command is:

```bash
npx figma connect publish --exit-on-unreadable-files
```

Publishing makes the template mappings available in Figma. After editing a template, publish again. Pushing commits to GitHub alone does not republish Code Connect mappings.

Commit the component URL changes too:

```bash
git add src/components/Button/Button.figma.ts src/components/Link/Link.figma.ts
git commit -m "Connect demo components to Figma library"
git push
```

## 8. Demonstrate the result

In Figma Design mode, select a Button instance on the Demo page or in the consumer file. Change its properties, then switch to **Dev Mode** and select the instance itself to inspect the connected React example. Toggle between Design and Dev Mode if property controls are unavailable while inspecting.

An example after choosing Secondary, Small, Disabled, and Label = Continue is:

```tsx
import { Button } from "./components/Button/Button";

<Button variant={"secondary"} size={"small"} disabled={true}>{"Continue"}</Button>
```

For Link, choose Muted and enable External:

```tsx
import { Link } from "./components/Link/Link";

<Link href="https://developers.figma.com/docs/code-connect/" variant={"muted"} newTab={true}>{"Read documentation"}</Link>
```

Whitespace in the Inspect panel may differ. The selected prop values, imports, and label should agree.

Copy the Button snippet into a file under `src` and render it, or compare it with the supplied playground. The implementation supplies native button semantics, disabled behavior, and focus styling. Code Connect supplies the mapped usage example.

If you change Figma instance values, the example reflects those values without republishing the template. If you change property names, mapping logic, imports, or source metadata, update and republish the templates.

## Common problems

| Symptom | Check |
| --- | --- |
| Code Connect is unavailable | Eligible organization, seat, file location, and file permissions. |
| URL or node validation fails | Replace both placeholder URLs with copied main-component-set links, including node-id. |
| Label or External cannot be read | They must be real exposed component properties, bound to the intended layers in every variant. |
| A variant maps incorrectly | Check exact capitalization and values in the table. No extra Hover or Focused variants are mapped in this experiment. |
| Snippet is absent in Inspect | Run connect:publish successfully, select a connected component instance rather than its text child, and open Dev Mode. |
| Connection exists but only a code path appears | The UI-only workflow does not supply these authored Inspect snippets. Publish the included CLI templates. |
| Changes in code are not reflected | Update the corresponding template and publish it again. |
| 401 or 403 | Token expiry, scopes, account access to the file, and Code Connect entitlement. |
| Source link does not open | Confirm the Git remote, main branch, source metadata path, pushed files, and viewer access to a private repo. You can set source to the full GitHub blob URL if needed. |
| CLI does not find files | Run at the repository root and retain the supplied figma.config.json include glob. |

## Removing only the experiment mappings

To remove one demo mapping, substitute its real library node URL:

```bash
npx figma connect unpublish --node "PASTE_BUTTON_COMPONENT_SET_URL" --label "React"
```

Repeat with the Link node only if needed. Afterwards, clear the token from the shell:

```bash
unset FIGMA_ACCESS_TOKEN
```

## What the presentation can conclude

Successful publication and inspection would demonstrate that a small, intentionally aligned library can supply useful component examples. You can report the measured setup time, property-mapping effort, and maintenance steps.

This experiment does not establish the integration cost for your existing design system, automatically synchronize Figma with code, or generate the implementation/CSS. For a later production assessment, inspect one actual Button or Link API with a developer who knows the codebase. The maintained template format can also emit HTML/Web Component snippets, so React in this starter is a demonstration choice.
